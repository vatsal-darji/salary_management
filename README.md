# Salary Management System

A full-stack salary management application built for HR managers to manage and analyse employee compensation data at scale (10,000+ employees). The system provides employee CRUD operations, advanced filtering, and salary analytics across countries, departments, and job titles.

## Architecture

The backend follows a three-layer pattern: **Repository -> Service -> Router**.

| Layer | Responsibility |
|---|---|
| Repository | Executes raw SQL against the PostgreSQL pool. Accepts an interface so it can be swapped with a mock in unit tests. |
| Service | Contains business logic, validation, and orchestration. Depends only on the repository interface. |
| Router | Thin HTTP adapter. Parses requests, delegates to the service, and returns responses. |

This separation ensures each layer is independently testable without a running database or HTTP server.

## Database Schema

### `employees` table

| Column | Type | Constraints |
|---|---|---|
| id | UUID | Primary key, generated by `uuid-ossp` |
| full_name | VARCHAR(255) | Not null |
| job_title | VARCHAR(255) | Not null |
| country | VARCHAR(100) | Not null |
| salary | NUMERIC(12,2) | Not null, >= 0 |
| department | VARCHAR(255) | Not null |
| email | VARCHAR(255) | Not null, unique |
| hire_date | DATE | Not null |
| created_at | TIMESTAMPTZ | Defaults to now() |
| updated_at | TIMESTAMPTZ | Defaults to now() |

### Indexes

| Index | Type | Purpose |
|---|---|---|
| `idx_employees_country` | B-tree | Filter by country |
| `idx_employees_job_title` | B-tree | Filter by job title |
| `idx_employees_department` | B-tree | Filter by department |
| `idx_employees_salary` | B-tree | Salary range queries |
| `idx_employees_country_job` | B-tree (composite) | Average salary by job title within a country without a full-table scan |
| `idx_employees_full_name_gin` | GIN | Full-text search on employee names |

## API Reference

All endpoints are prefixed with the backend base URL (default: `http://localhost:3001`).

### Employees

| Method | Endpoint | Description |
|---|---|---|
| GET | `/employees` | List employees with optional filters and pagination |
| GET | `/employees/:id` | Get a single employee by ID |
| POST | `/employees` | Create a new employee |
| PATCH | `/employees/:id` | Partially update an employee |
| DELETE | `/employees/:id` | Delete an employee |

**Query parameters for `GET /employees`:**

| Parameter | Type | Description |
|---|---|---|
| country | string | Filter by country |
| department | string | Filter by department |
| jobTitle | string | Filter by job title |
| search | string | Full-text search on employee name |
| page | number | Page number (default: 1) |
| pageSize | number | Results per page (default: 20) |

**Request body for `POST /employees`:**

```json
{
  "fullName": "Jane Smith",
  "jobTitle": "Software Engineer",
  "country": "India",
  "department": "Engineering",
  "email": "jane.smith@example.com",
  "hireDate": "2023-06-01",
  "salary": 95000
}
```

All fields are required. `email` must be unique. `hireDate` must be an ISO 8601 date. `salary` must be a non-negative number.

**Request body for `PATCH /employees/:id`:**

All fields are optional. Only the provided fields will be updated.

### Insights

| Method | Endpoint | Description |
|---|---|---|

| GET | `/insights/by-department` | Average, min, and max salary grouped by department |

## Getting Started

### Prerequisites

- Node.js >= 20
- Docker and Docker Compose

### 1. Start the databases

```bash
docker compose up -d
```

This starts two PostgreSQL instances: one for development (`localhost:5432`) and one for tests (`localhost:5433`).

### 2. Set up the backend

```bash
cd Backend
npm install
```

Create a `.env` file in `Backend/` (see [Environment Variables](#environment-variables)), then run the migration and seed:

```bash
npm run migrate
npm run seed
```

Start the development server:

```bash
npm run dev
```

The backend runs on `http://localhost:3001` by default.

### 3. Set up the frontend

```bash
cd Frontend
npm install
npm run dev
```

The frontend runs on `http://localhost:3000` by default.

## Running Tests

All test commands should be run from the `Backend/` directory.

```bash
# Unit tests (no database required)
npm test

# Unit tests in watch mode
npm run test:watch

# Unit test coverage report
npm run test:coverage

# Integration tests (requires test database to be running)
npm run test:integration
```

### Test structure

**Unit tests** (`tests/unit/`) cover the repository and service layers in isolation using mock dependencies. No database connection is required.

**Integration tests** (`tests/integration/`) run the full HTTP stack against the test PostgreSQL instance using Supertest. They verify end-to-end request handling including validation, error responses, and database interactions.

## Design Decisions

| Decision | Alternative Considered | Rationale |
|---|---|---|
| PostgreSQL | SQLite | Better support for concurrent load, composite indexes, and aggregation queries at 10,000+ row scale |
| Repository pattern | Active Record / ORM | Clean separation between data access and business logic; repository interface enables unit testing without a real database |
| UUID primary keys | Serial integers | Avoids enumeration attacks and is safer for distributed or future multi-service architectures |
| `NUMERIC(12,2)` for salary | `FLOAT` | Eliminates floating-point rounding errors on monetary values |
| Bulk `COPY` for seeding | Individual `INSERT` statements | Seeding 10,000 rows via `pg-copy-streams` in batches of 500 is an order of magnitude faster than row-by-row inserts |
| GIN index on `full_name` | `LIKE` with B-tree | Enables efficient full-text search without sequential scans |
